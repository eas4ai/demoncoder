# CODE-004 mechanism review

Reviewed 2026-09-06 against the agreed requirement and falsifier.

The driver opens the production terminal for each initial connection in a
fresh temporary Git repository. Its first response queues a held Bash tool
and a write to a superseded marker. The driver submits a unique correction
through the editor while Bash is waiting. Before releasing Bash, it requires
a rendered acknowledgement and its exact retained event, with no completed
tool or turn. Terminal cursor updates can split words, so the rendered check
matches the acknowledgement prefix and the event check verifies its full text.

After release, both native provider peers inspect their next actual request:
it must contain the original successful Bash result, an unexecuted result
for the superseded call, and the correction. External peers require the
completed Bash result before interruption, retain the backend identity, and
send another stale tool request after interruption starts. Both old requests
must be denied. They send turn completion before the interruption reply to
exercise that ordering. Only after those barriers do they accept a corrected
prompt. The next model decision requests a real write containing the correction.
The driver checks that file, absence of the superseded marker, exactly two
executed tools, and their actual results and identities.

Failure demonstrations executed:

- The first driver run against the preceding executable failed all four
  acknowledgement checkpoints (exit 1).
- `python3 tests/steering.py --fault-drop-correction` omits submission of the
  drafted correction and fails all four acknowledgement checkpoints (exit 1).
- `python3 tests/steering.py` passed all four cases after implementation.

A Rust process test consumes part of a JSON frame, cancels the receive future,
then releases the remaining bytes and checks the complete parsed message.
Keeping partial bytes on the connection prevents steering from losing data.

Codex interruption fields were checked against JSON schemas generated by the
installed app-server: threadId and turnId are required. Claude interruption
uses its [SDK control request](https://raw.githubusercontent.com/anthropics/claude-agent-sdk-python/main/src/claude_agent_sdk/_internal/query.py).
The host does not replace either external model loop. These protocol cases
still do not establish installed backend or live service compatibility.
Live transport and complete external tool confinement remain separately
required by the commitment. Cancellation and arbitrary coding correctness
are outside this check's claim.
