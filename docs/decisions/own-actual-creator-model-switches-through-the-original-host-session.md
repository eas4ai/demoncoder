## Decision

Own an eligible Creator model change as one durable ModelSwitch operation in the existing runtime ledger. Keep Settings admission unchanged: a new eligible prompt captures its resolved assignment, and running, queued, interrupted or explicitly overridden work keeps its original connection. The captured candidate retains the previous access policy and original host-session lifetime and allowance. A saved default or label-only change is not a model-switch event. Do not reread a different settings selection after gates have inspected the captured one, borrow task or child funding, issue a fresh grant, or introduce a second allowance ledger.

If PreModelSwitch refuses the change, do not run its dependent new submission on the old provider. The submission captured the selected connection; an intake acknowledgment does not authorize another model or account. Retain the submitted text through the existing conversation/error path, visibly report that the refused switch prevented execution, and require a fresh explicit submission or repair through existing controls. Do not introduce automatic replay or a new queue. Previously running, queued and interrupted work keeps its own original pins and records.

Pin the old and requested connection identities, actual model values, source, workspace, original frozen policy digests and exact occurrence. Run PreModelSwitch before the provider change, using existing bounded runners, inspected read sets and final-candidate admission. Recheck owner, policy, selection, cancellation, recovery state and required snapshot revisions at the serialized transition boundary. Changed facts hold the action without replaying effectful gates. Native declarations use all five existing handler types. Retain the existing grant-free synchronous command rule; prompt, agent, HTTP and MCP execution requires the original explicit session allowance and existing service limits. Unavailable or exhausted funding cannot fall back to another owner. Bind any developer question to this exact candidate and authenticated control; an unavailable answer route is a visible hold, never permission.

Use the existing host replacement path for cross-provider changes, an uninitialized backend or changes beyond the model. Prepare the replacement without admitting provider/model work. After allowing gates and final validation, stop owned observers and close the old provider before publishing the new durable binding; do not preserve the current bind-before-close inconsistency. Keep durable publication and live connection installation together with no intervening await. Record the stage and retain a recovery hold when teardown or publication becomes uncertain. A refusal before teardown preserves the old connection and admitted work. Once the provider change applies, retain that outcome; later receipt, settings-control activation, cancellation or delivery failure cannot report a clean denial or restore stale provider state. Emit ModelAssignment and native PostModelSwitch only for the actual applied identity. Post is an observer: an ordinary observer error stays visible without undoing the switch or becoming a new policy gate. Actual ownership, persistence or delivery uncertainty may still hold further execution under existing recovery rules.

For an already initialized Claude session, allow a narrowly checked model-only change through its real SDK set_model control. Adapter, account, credentials, binary, effort, access, workspace and all other relevant configuration must remain identical. The host owns and correlates that same switch; use a dedicated callback owner rather than relaxing turn-specific callback checks. Register unpredictable callback identities and bind the live backend/session, selected models, sequence and original deadline. Drive the genuine PreModelSwitch callback before acknowledging permission. Continue receiving after the set_model success response to observe the real PostModelSwitch callback. Retain the actual applied result before invoking post handlers, suppress duplicate host/source delivery and preserve uncertain effects on disconnect or cancellation. Never infer the source event from a success response alone or replay the SDK operation after uncertainty. Missing, malformed, stale or forged source data and relay failure must not release the guarded transition.

Claude command, HTTP and MCP declarations consume the genuine source payload, including required cache and pricing facts. Do not fabricate those facts for a generic host replacement. If an applicable required source policy cannot be represented on the selected path, visibly hold that transition instead of skipping the policy or converting its dialect automatically. Codex has no source ModelSwitch callback; native host events remain truthful there. Preserve explicit source/native selection, existing MCP reuse fingerprints and exact native startup/end identity checks. The switch owner may distinguish its captured pre-change identity from the actual applied post-change identity only within that exact transaction and its original allowance; it grants no general identity exception. Complete source conversion, public recovery controls and all remaining compatibility obligations stay in the selected commitment.

Demonstrate a denied real switch with unchanged provider requests, then an allowed switch with actual old/new requests and exactly attributed pre/post receipts. Cover both native API owners and the installed external owners, all applicable actual runner types, original counters/deadlines, no-op and explicit override cases, stale inputs, held unrelated work, pending settings attempts, cancellation, backend close and persistence failures, restart without replay, observer errors and bounded context. Qualify genuine installed Claude denial/allow and relay-loss boundaries separately from controlled peers. Preserve exact commands, candidates and raw results, including violating controls.
