Would be wrong if: Startup waits for a transferred command, a job or delivery borrows task authority, transfer consumes once, uncertain work replays, terminal output starts a turn, or actual cleanup exceeds the existing host boundary.
History: Extend the realized original-owner async decision and explicit session grant policy while preserving the reviewed native lifetime, shutdown reserves and source applicability correction. Native rewake remains excluded by its existing source validation; this does not change ordinary model or tool accounting.

## Decision

Enable explicitly declared asynchronous native SessionStart and SessionEnd Command observations only under the original explicit SessionHooks time grant and actual live native host. Synchronous commands remain grant-free. Async commands and context delivery do not spend model, backend or Agent inspection-tool slots. Preserve configured command timeouts and shared capacity limits. Missing, expired, replaced or held session authority cannot borrow a task allowance. Preserve the native-only session declaration boundary: native asyncRewake and Claude-only first-line transfer remain unavailable. Existing task and Claude continuation keep their current semantics.

Reuse the existing durable hook ledger, original Operation budget and in-memory native host authority. Capture the exact reserved hook, immutable admission and declaration, original budget, view and cancellation identity before effects. Transfer must be durable before startup releases ownership. Revalidate after persistence and before effects and delivery. After legitimate transfer, require the exact pending hook, its durable transfer and the original live host; a settled startup occurrence does not end that authority. A historical receipt cannot recreate it. Late settlement may retain the original outcome without restoring execution or delivery permission. If a compiled control demonstrates ordinary observer replacement accepting the wrong budget epoch, repair that same exact-owner boundary without changing task accounting.

Successful startup must release readiness before a delayed transferred command completes. Exclude only exact live transferred jobs from its observation drain and avoid taking an unused final validation lock. Keep immutable snapshots, configured write authority, mutation guards, process supervision and capacity through actual teardown. Validate pinned workspace and effective protected roots without treating a command's permitted output write as substitution of its immutable snapshot. Unrelated task cancellation, completion, acceptance, archive or replacement cannot revoke or replenish session work. Quiesce same-workspace session writers before evidence and replacement snapshots; do not extend their original deadline or make child work wait on unrelated parent writers.

At actual final termination, revoke outstanding startup observers and withhold their pending context. Preserve known outcomes separately; uncertain effects retain existing recovery holds and can prevent new terminal effects. Admit and join SessionEnd observers only within the original two-second end observation window, then revoke all host work and retain the existing three-second cleanup reserve. Keep the five-second whole end boundary, eight-second application reservation and thirty-second startup boundary. Cancelled startup must also stop earlier transferred jobs before cleanup completes. Reuse the existing host guard on abort or drop, including when runtime and event handles remain retained. Own actual processes, descendants and cleanup until teardown; no detached replacement lifetime or new allowance.

Deliver at most the existing 64 KiB bound of attributed startup context only to an already admitted native Creator model request in the same live host. Reserve delivery durably against the original exact hooks, retain its target request identity, and revalidate the host, original grant and view after persistence and immediately before the request. That existing request keeps its original debit. Completion itself cannot start a request, select or mutate a task, invoke developer controls or enter the post-response correction path. A later task can receive valid session context without becoming the observer's owner or funder. Withhold terminal context. Interrupted delivery does not replay automatically.

If context authority ends before text enters the model, durably withhold that contribution and let the independently admitted ordinary request proceed without it. The existing Model API can append and checkpoint context but cannot roll it back. If authority ends after those model changes, retain the partial-delivery history and recovery hold; do not send invalid context or claim that the provider received it. Once a valid request was sent, retain its successful response and settle the original delivery target even if the session grant expires while that response is pending. Recording that known outcome grants no new execution authority. This preserves the rule that an observer failure does not replace an observed operation's result without introducing a model rollback framework.

Launch and transfer are not one-shot success. Consume once only after exact valid actual success; retain unknown effects and delivery for reconciliation without replay on restart. Preserve eight active observers and 64 pending deliveries, release active permits only after cleanup, and prune completed withheld or delivered capabilities. Demonstrate actual readiness, effects, context, original accounting, expiry, cancellation, authority changes after persistence, uncertain restart, saturation, writer quiescence and descendant cleanup with compiled violating controls and corrected cases. Preserve current session command/model/HTTP/MCP and ordinary task/child async behavior. Public activation, source conversion, actual external lifecycle qualification and full conformance remain required work in this same commitment.
