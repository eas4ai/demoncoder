# Bind MCP hook calls to admitted managed services and explicit protocol versions

Level: Judged
Decided by: agent
Rests on: PLUG-002,PLUG-003,PLUG-011,PCOMP-002,PRUN-001,PRUN-002
Would be wrong if: A service call escapes its admitted identity or owner, repeats an uncertain effect, discloses credentials, or treats an unsupported protocol as compatible.

## Decision

Build managed MCP stdio and Streamable HTTP connections with immutable host service identity, explicit tool and credential authority, bounded initialization/discovery/calls, and shared owning admission. Keep package code, configuration, workspace, role, state generation and credential binding in reuse identity. Use the initialization-based 2025-11-25 protocol as the first explicit qualification target; negotiate only versions whose behavior is implemented and tested, never infer compatibility from a newer version string. The pinned Codex rmcp 3.1.3 dependency defaults to 2025-11-25. Reuse existing confinement, strict plugin parsing, HTTP authority and durable uncertain-outcome boundaries; a transport library must not bypass them. A hook resolves source input placeholders as data and invokes an already admitted managed service/tool; it cannot bootstrap itself through its own hook chain. Preserve structured/text source result semantics and isError failure. Separate service connection recovery from effectful tool execution: no automatic retry of an uncertain tools/call. Unadvertised server requests cannot gain filesystem, model or developer authority. Public configuration, authentication UI, full lifecycle notifications and channels follow under the same complete commitment and must still pass the pinned real-package cases.

Use a small strict wire client with existing transport dependencies. Add ryu-js 1.0.3 only for ECMAScript number formatting in Claude placeholder values, including nested JSON strings; its registry checksum is 04d056b875a9d2e6cb9a61d127afee9ac5999b9f87bcb32079d1318e505be714 and its license is Apache-2.0 OR BSL-1.0. Controlled pinned-Claude probes establish the required formatting and rounding cases. The inspected rmcp transport includes automatic reconnect and per-request metadata behavior that would need additional restriction; no SDK source is copied. Add an explicit duplex payload-input descriptor mode to the existing hook supervisor, retaining its separate lifetime lease, launch gate, descriptor validation and known descendant shutdown. Ordinary command file-input mode remains covered by its regression tests. Unknown stream continuation holds instead of resuming or replaying an effectful call.

Service ownership derives from the existing stable session/task/role authority and original deadline, separately from each current hook operation. Reuse across sequential operations must not renew its allowance or treat changed usage counters as a new owner. Source placeholder policies remain distinct: pinned Codex preserves a sole replacement value type and rejects missing fields; controlled pinned Claude runs stringify replacement values and use empty strings for null or missing fields. Native uses the typed policy. All expansion remains bounded data processing, never shell source.

Bound live managed services with eight capacity slots shared by the existing runtime across manager instances. This is an in-memory resource bound, not another task or model allowance. Keep it separate from the transient hook-runner permits so idle connections cannot exhaust the slots needed to call them again. Startup and active calls retain their original execution permits until their response is complete or teardown is known; idle services retain their service ownership and capacity. Failed startup and known shutdown release capacity. Saturation is visible and cannot start unaccounted processes.

Prepare managed dependencies in a host-owned phase before reserving or dispatching a hook group. Persist a bounded PluginService host-operation receipt in the existing operations ledger before initialization traffic; bind it to the owning operation and immutable service identity. Initialization and discovery complete that dependency operation, not a hook invocation. The MCP hook runner requires a ready service and only invokes its selected tool. Failed or interrupted bootstrap holds the group; uncertain initialization remains unreconciled and is not automatically retried. Service startup cannot recursively invoke hooks. Distinguish a concurrent initialization already in progress from a known dependency cycle. These records use the existing owner and allowance and preserve old serialized operation variants.

Declared placeholder access is to JSON event fields. Pinned Claude also exposes inherited JavaScript prototype properties through its resolver; those are host-runtime objects, not fields in the event payload. Reject such access explicitly before service traffic instead of emulating native functions or silently treating them as missing fields. Reject source template keys that invoke prototype assignment rather than JSON field construction. Own JSON event fields with those spellings remain data and take precedence. Ordinary missing Claude fields keep their observed empty-string result. This boundary must remain visible in validation and diagnostics.
