## Decision

Gate the existing in-session Settings save before its private atomic publication. Capture the currently active frozen plugin policy, session/workspace identity, current settings revision and a digest of the validated proposed configuration. Use the existing typed lifecycle dispatcher, source-specific result decoding, inspected snapshots and durable admission/outcome receipts. Actual user Settings uses ConfigChange source user_settings; it cannot label itself managed policy. Native declarations support all five existing handler types; imported Claude declarations retain their command/HTTP/MCP applicability and dialect outcomes. No Codex ConfigChange callback is invented. Initial code-free onboarding without an active plugin policy remains initial setup, not an observed settings replacement.

Run asynchronous inspection outside the Settings state mutex and private publication lock. The old generation judges the proposal; proposed code or settings cannot approve themselves. Bind passes to the exact draft, old disk revision, active generation, workspace inputs and original owner. Revalidate those facts at the existing serialized compare-and-publish boundary. Preserve the existing conflict and invalid-save refusal, private storage permissions and post-rename publication-uncertainty handling. A denied, stale, failed, cancelled or timed-out gate leaves the proposal unapplied and its attributed reason visible. Do not replay effectful handlers to refresh a stale pass. Once publication occurs, retain the applied/uncertain outcome rather than writing stale settings back or calling it a clean refusal. Retain the original durable operation when recording its outcome fails. A direct ordinary save must not bypass an attached active policy.

Settings is an explicit developer session control, not work on an unrelated running task. Extend the existing durable host lifetime, SessionHooks allowance reference and non-tool receipts to own this control on all four connections. Preserve native SessionStart/End observations at their actual native boundaries and external lifecycle delivery at its actual backend callbacks; owning a host Settings operation does not establish an unobserved source callback. Capture the original explicit session grant for handlers that require it, even while coding work is active. Reuse its existing cumulative counters and deadline; do not borrow task or child funding, issue a fresh grant, or add a parallel allowance ledger. Replacement, cancellation, shutdown and recovery invalidate unfinished invocation authority without replaying uncertain effects. Changing a default does not change an already admitted model, account, task, child or allocation.

Keep host-control lifetime authority distinct from current provider identity. A later eligible Creator replacement changes the current provider identity without renewing the original session allowance. A new settings attempt captures that current identity and frozen policy; an unfinished attempt from a replaced provider remains invalid. This extension must preserve the exact owner checks of existing native startup/end, compaction and service invocations. Do not relax their identity checks globally to make settings work.

Keep Settings responsive while a gate runs. Cancelling or closing the proposal cancels and joins its owned handlers within the existing bounds without cancelling unrelated coding work; application shutdown retains its current cleanup deadline. Gate frames and inspected proposal summaries contain only allowed configuration structure and opaque revision/binding identifiers. Credentials and private settings contents never enter prompts, snapshots, ordinary logs or hook output. Preserve private-source export protections and provider/authentication selection semantics.

Prove actual saves and unchanged denied state through the production Settings API/control path, including native and external connection owners, an unrelated active task, original session funding, all applicable handler/source pairs, changed drafts and concurrent disk edits, cancellation and shutdown, malformed replies, missing grants and publication failure. Safe violating controls must demonstrate the gate and stale-publication protections before their corrected cases pass. Retain exact commands, candidate inputs and raw results. Run affected terminal/settings and owner regressions, then independent specification and quality reviews and the full regression. Workspace operations, dynamic watches, actual model-switch events, plugin activation/recovery controls and the rest of the lifecycle matrix remain subsequent work in the same complete commitment; this prerequisite does not discharge them.
